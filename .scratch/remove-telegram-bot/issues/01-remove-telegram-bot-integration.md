# Remove the Telegram Bot Integration

Status: done
Category: enhancement
Type: AFK

## Agent Brief

**Category:** enhancement
**Summary:** Completely remove the unfinished Telegram Bot intake channel while preserving historical Diary provenance and the supported Web and AI Agent Partner paths.

**Current behavior:**

The application contains a webhook-driven Telegram Bot that can link a Telegram identity to a User and create a Diary or Transaction through chat commands. The integration owns account-linking codes, sessions, processed-update idempotency, cleanup scheduling, runtime configuration, deployment secrets, HTTP handlers, translations, operational scripts, documentation, and four Telegram-specific database models.

The domain documentation marks Telegram Bot as an unfinished channel with known failures. It is not required by the core Diary workflow. Telegram Diary writes already delegate to the shared Diary write module, so removing the channel does not require replacing its Diary or Transaction behavior.

Telegram-specific authentication and CSRF exemptions currently widen the unauthenticated request surface. Deployment configuration also carries Telegram secrets and a public bot username even when the channel is not operational.

**Desired behavior:**

The application should have no runnable, configurable, deployable, or user-visible Telegram Bot integration. Telegram webhook requests and account-linking requests should resolve as ordinary nonexistent routes. Authentication and CSRF processing should no longer contain Telegram-specific exceptions.

The four Telegram-specific tables should be removed through a forward database migration. Their account-linking, verification, session, and processed-update data are no longer product data and do not need an application-level export path. Production operators remain responsible for normal database backup policy before applying a destructive migration.

Existing Diaries created through Telegram must remain readable and retain their historical `TELEGRAM_BOT` provenance. The legacy Diary source value therefore remains valid for stored Diary records, but no active write path may create new Telegram-sourced Diaries.

The Web Diary path and the standard AI Agent Partner path must continue to use the existing shared Diary write behavior without Telegram-specific branching.

**Key interfaces:**

- `Diary.createdVia` / `TELEGRAM_BOT` — retain the historical value so existing Diary provenance is not rewritten or made unreadable; remove it only from active input types where doing so does not invalidate persisted rows.
- Runtime configuration — remove the bot token, webhook secret, and public bot username settings.
- HTTP routing and request middleware — remove all Telegram handlers plus webhook-specific authentication and CSRF exemptions.
- Telegram persistence — remove account, verification-code, session, and processed-update models and their User relations through a forward migration.
- Deployment configuration — remove Telegram environment variables and secret entries from local examples, Kubernetes manifests, and deployment instructions.
- Package surface — remove Telegram libraries and webhook-management commands when they have no remaining caller.
- Documentation and localization — remove Telegram workflow, operations, testing, README, and locale content while keeping historical migration files intact.
- Logging — remove the Telegram-specific logger namespace if it has no remaining caller.

- [ ] No production route accepts Telegram webhook, code-generation, binding-status, or unlink requests.
- [ ] Authentication and CSRF middleware contain no Telegram-specific bypass or skip path.

- [ ] Package dependencies and package scripts contain no Telegram Bot framework, i18n plugin, conversation plugin, or webhook-management command unless an independently verified non-Telegram caller still requires it.

- [ ] Historical migration files are not rewritten or deleted.
- [ ] Existing Diary records with `createdVia = TELEGRAM_BOT` remain valid, serializable, and readable after the migration.

**Out of scope:**

- Replacing Telegram with another chat, messaging, or quick-capture channel.
- Changing Quick Note or the Web Diary authoring experience.
- Changing AI Agent Partner authentication or creating a special AI write path.

- Editing or deleting historical database migration files.
