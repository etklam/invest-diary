  Issue 1: BUY/SELL 配對策略

⏺ User answered Claude's questions:
  ⎿  · [P1] (confidence: 9/10) 績效儀表板的核心問題是 BUY/SELL 配對策略。計算「單筆交易損益」需要把 SELL 配對回對應的 BUY。有三種做法：

     ```
     配對方法比較
     ═══════════════
     平均成本: SELL 損益 = (賣價 - 平均成本) × 數量
                → 與現有 calculateHoldings() 一致
                → 台股投資人熟悉的計算方式
                → 簡單可靠

     FIFO:      SELL 配對最早的 BUY 批次
                → 更精確但更複雜
                → 需要新的 batch tracking
                → 與現有邏輯衝突

     只做總統計: 不配對，只算準別 P&L
                → 最簡單但沒有單筆分析能力
     ```

     這會影響整個績效系統的計算基礎。平均成本法與現有程式碼最一致，且對個人投資者來說夠用了（專業 trader 才需要 FIFO 精確配對）。

     RECOMMENDATION: 選 A。與現有 calculateHoldings() 一致，避免兩套算法產生矛盾的數字。符合「明確優於巧妙」。未來想升級到 FIFO 時，可以在
     matchTrades() 裡換就好。Completeness: A=8/10, B=10/10, C=4/10 → A) 平均成本法 (推薦)

     ```sql
     SELECT * FROM transactions
     WHERE user_id = ?

     ```

     比現在的 `WHERE diary.userId = ?`（需要 JOIN）更快。

     RECOMMENDATION: 選 A。單一查詢 + 記憶體計算對這個規模最合理。userId 欄位是關鍵——它消除了通過 diary JOIN 的開銷。加一個 `@@index([userId,
     tradeDate])` 就完了。Completeness: A=9/10, B=5/10 → A) 一次載入 + 記憶體計算 (推薦)
