# ADR-0001: 日記優先架構 (Diary-First Architecture)

## 決策

日記（Diary）是系統的核心聚合根，交易（Transaction）是日記的可選附件。一筆交易不能獨立存在，必須附屬於一篇日記。

## 原因

目標使用者（0-3 年新手）的交易頻率極低——一個月可能零到一筆交易。但每日市場觀察（日記）應該是持續的習慣。如果系統以交易為中心設計，大部分日子使用者打開 app 會看到空白頁面，無法建立持續使用的動力。

Quick Note（快速記錄入口）的存在就是為了支撐這個設計——即使當天是「無效市場、沒事發生」，使用者也能用最少時間完成一篇日記，養成習慣。

## 取捨

- **選了**：日記為核心，允許空日記（無交易），交易必須掛在日記下
- **沒選**：交易優先架構（每筆交易獨立存在，日記可選附加）——這對高頻交易者更合適，但對新手是錯誤的模型
- **沒選**：日記和交易完全分離（兩個獨立實體，可選關聯）——增加複雜度但對新手無價值
